摘  要
近几年，随着医疗数字化建设的不断推进，医院病历管理系统已成为国家“健康中国”战略目标不可或缺的组成部分。对于提高医疗机构的运行效率，增强医疗服务的安全性发挥着关键性的作用。尽管如此，我们在推广信息化病历和提高工作效率等方面仍面临许多困难和挑战。
鉴于此，本文阐述了一种利用 SpringBoot 框架的医院病历管理系统的创新及其执行。该系统运用了当前广泛接受的前端和后端独立结构，通过这种设计，系统能够提供灵活、高效且易于维护的服务。在前端部分，利用 Vue 的组件化特性，创建了患者列表等界面组件，主要实现了预约挂号功能、就诊信息和住院登记等主要功能。此外更好的实现了前后端的数据实时共享，并使用 Axios 库与后端 RestfulAPI 进行数据交互，实现了患者信息的展示和操作。结合 JPA 规范和 MySQL 数据库，后端实现了患者信息的持久化存储，并通过定义 Controller 层的方法对外提供 API 服务。系统的整体设计考虑了可扩展性和维护性，通过该模式将用户界面、数据处理和业务逻辑清晰地分层。
综上所述，本文设计的医院病历管理系统既满足了基本的业务需求，又具有良好
的用户体验和较高的开发效率。该系统具有一定的实用价值和推广前景。
关键词：病历管理；前后端分离；SpringBoot
ABSTRACT
In  recent  years,  with  the  continuous  advancement  of  medical  capitalization,  the hospital medical record management system has become an indispensable part of the national "Healthy China" strategic goal. It plays a key role in improving the operational efficiency of medical institutions and enhancing the safety of medical services. Despite this, we  still  face  many  difficulties  and  challenges  in  promoting  information  and  medical records and improving work efficiency.
In view of this, this paper describes the innovation and implementation of a medical case management system using SpringBoot framework. The system uses the currently widely accepted front-end and back-end separate architecture, with the front-end creating the user interface through Vue.js. On the back end, the SpringBoot framework greatly reduces the configuration and installation steps of traditional Spring applications, allowing developers to quickly structure projects. With this design, the system is able to provide flexible, efficient and easy to maintain services. In the front end, Vue's component-based feature is used to create interface components such as patient list, and Axios library is used for data interaction with the back-end Restful API to realize patient information display and  operation.  Combined  with  JPA  specification  and  MySQL  database,  the  backed implements  persistent  storage  of  patient  information,  and  provides  API  services  by defining the Controller layer. The overall design of the system considers the scalability and maintainability, and through this model, the user interface, data processing and business logic are clearly layered.
To sum up, the hospital medical record management system designed in this paper not only  meets  the  basic  business  needs,  but  also  has  good  user  experience  and  high development  efficiency.  This  system  has  certain  practical  value  and  popularization prospect.

1  绪论
1.1  研究背景与意义
1.1.1 研究背景
随着我国医学科学不断的进展和现代计算机时代的到来，计算机早已渗入了人类日常生活的各个领域。尤其是和人类的生活密切关联的衣食住行各产业受到了巨大的冲击。在互联网的带动下，医院业务也取得了稳健的成长。另外，在国家二十大新政策的推动下，中国经济社会也进行了快速的发展，人民百姓的生活水平也日益提升，卫生知识也越来越深入人心，对医院服务质量的要求也越来越高。在数字化时代，医院已经累积了大量关于患者病史的数据，这些数据对于患者的诊疗和医疗决策至关重要。但传统医院档案管理系统在处理不断增长的医疗数据和保护隐私安全方面存在诸多问题。首先，许多传统系统采用集中式存储方法，将所有信息集中在一个服务器或数据中心。这种集中存储方式容易成为攻击目标；如果服务器或数据中心受到损害，数据可能会被破坏、丢失或被窃取，从而导致严重的隐私和安全问题[1]。病历记录了患者病情、诊疗、康复等重要信息，是医生进行临床诊疗的关键依据。病历在医疗服务中具有重要价值，不仅用于临床教学、医学研究，还常用于医疗质量控制管理和国内外医院交流，因此属于医院管理的关键内容。为保证病历的完整性和正确性，需要通过整合大数据技术等先进手段，完善病历信息管理系统，提高信息管理的准确性，提高医疗服务的质量和效率，对于提高医疗效率、质量和服务水平具有重要意义[2]。
传统的病案管理方法有其固有的弊端，其中纸质病案因其物理性质而不利于长期保存、
快速查询和有效管理，它们易于损坏、遗失，且限制了医疗信息的流通与利用。
因此，建立电子病案管理系统已成为一种必然趋势。医院病案管理系统是指运用计算机技术和信息管理理论，对医院业务进行信息管理的系统。综上所述，医院病案管理系统的研究背景主要包括医疗信息化的发展、传统病案管理的不足、电子病案系统的优势以及医院电子媒体建设中存在的问题。
1.1.2 研究意义
目前，我国大多数城市的大中小型医院都有各种不同规模的医院病案管理系统。虽然电子病案系统在医院信息化管理系统中具有重要意义，但目前医院电子病案系统建设中还存在系统功能不完善、数据质量不高、系统稳定性不强等问题。因此，研究和开发一种更加实用、高效、稳定的医院用药具有重要意义。
医院病历管理系统成为医院数字化建设的关键发展方向，无论是对于患者、医疗
机构还是医疗人员都拥有特别的价值，主要表现在以下几个方面：
（1）提高工作效率和质量。现代医疗标准要求高效、精准的治疗和服务，推动医院采纳了该病历系统。此系统优化了临床工作复杂的流程，改善了医生编写病历的效率，减轻护士记录负担，减少了出错现象。无纸化快速反馈和网络辅助诊断支持医
1
生做出更好的治疗决策。总体而言，医院病历系统为医务人员提供了强大的工作支持，
确保患者接受到更优质的医疗服务。
（2）提高医院的操作机制。实施了该病历系统后，医院能即时收集各种历史性数据，建立规范化指数，并能够提供实时的反馈。在对不同领域，使得医院能够进行有效监管，优化整体管理流程。通过这种持续的数据整合和分析，医院管理体系得以全面提高和完善。
（3）实现内部信息实时共享。电子病历管理系统极大地促进了患者治疗信息在医院内部或者其他医院实现流通与共享。当患者身体情况不见得好转，需要转院时，其电子病历档案可以轻松地并入新医疗机构的系统中，确保了医疗连续性和及时性。这提高了患者获得连贯护理的能力，避免了信息延误，有助于维护患者的健康和安全。
综上所述，研究医院信息管理系统可以帮助医院提高工作效率、提升医疗服务质量，对于改善医疗行业的管理和发展具有重要意义。因此，开发一套高效、安全、可靠的医院病历管理系统已经成为了当今医疗行业的迫切需求。

医疗质量，还可以减少整个医疗行业的许许多多的不必要开支。

3.1  系统需求概述
系统需求分析是软件开发生命周期中的早期阶段，旨在理解用户需求，确定系统功能和特性，并设计出最佳解决方案。这些需求是软件系统成功实现的基石，因此需求分析成为软件开发过程中不可或缺的环节。系统需求分析的重要性不容忽视，它为开发人员提供了明确的方向，并确保他们按照用户需求进行开发。此外，需求分析也是项目成功的关键，因为它有助于减少后期修改和返工的可能性，提高开发效率，降低开发成本。

3.2  功能需求分析
本系统种门诊患者就诊的第一个步骤为挂号，本系统对于当天的医生是否上班信
9
息进行了实际的设计，结合当天的时间，在患者端的预约挂号页面上显示当天已经关联医生的排班信息，即医生值班信息。罗列出患者所关注的信息，如医生简介，医生所擅长的领域等等，以上信息均方便于患者挂号就诊。如果是新诊断的患者，则需要先进行注册操作，生成唯一的就诊ID号，并由系统匹配相应的编号发给患者，每位患者都有专门的就诊编号。当病人用完这个号码后，你可以在病人这边查看你和医生预约的时间段，提醒病人根据已经叫号的信息进行就医诊断。接下来便是就诊流程了，门诊医生根据患者的病情进行诊断，并根据病情开出相应医嘱处方项目，该项目主要内容主要包括患者基本病情、是否需要住院登记、是否需要缴费操作和是否是医保等等信息。所有项目都需要先在门诊收费平台进行支付，支付后的信息会推送到每个项目对应的科室。如果是处方，在患者完成缴费后，系统会主动推送给患者的病历信息，等候药房工作人员完成处方取药。此外对于系统维护等操作，需要系统管理员角色。作为管理员，对系统具有最高权限，具有界面显示功能的操作权限，包括普通用户的注销、修改帐号等功能。同时，还需要维护系统的一些基本信息，如科室信息、医生排班信息、挂号信息等。
总的来说，系统需求分析是软件开发过程中的重要环节。本医院病历管理系统主要包括以下十大功能：患者管理、医生管理、预约挂号管理、医生排班管理、就诊信息管理、住院登记管理、病历信息管理、科室信息管理、公告管理、缴费管理。

3.5  非功能性需求分析
除了上述的功能要求之外，医院病案管理系统还必须满足多项非功能性要求。本章将重点从数据保密性、用户验证与授权以及系统鲁棒性三个角度对这些非功能性需求进行详尽阐述和探讨。
（1）数据保密性：保障医院病历数据在保存与传递时均以加密形式存在，以避免未授权获取和信息泄露的风险。
（2）用户验证与授权：系统应提供严格的身份认证机制，确保只有经过授权的用户才能访问病历数据，并且不同用户应有不同的权限级别，以实现数据的分级访问。
（3）系统鲁棒性：系统应具备一定的容错能力，能够自动检测和纠正错误，防止因软件缺陷或操作失误导致的数据损坏或丢失。
这些非功能性需求是电子病历管理系统设计和实施过程中不可忽视的重要方面，它们共同构成了系统质量的保障基础。在开发过程中，需要充分考虑这些需求，并采取相应的技术手段和管理措施来确保它们得到满足。

3.7  系统数据流分析
数据流图（DFD）是一种用于描绘数据流向和处理活动的视觉表示方法。它由四种基础要素构成：数据流本身、流向路径、数据处理节点、以及数据存储和外部实体。数据流映射出在系统内部移动的数据，流向路径则指示数据传递的方向。处理节点代表对数据执行的操作，而数据存储涉及数据的保存和提取。外部实体则指与系统交云互动的非内部元素。数据流图按层次组织，从概览级的上层图到具体细节的下层图，每一层都提供了系统不同方面的视图。数据流图帮助用户和系统分析师理解系统的内部结构，从而更好地控制和管理各个系统组件。

7  结论
本文深入探讨了医院病历管理系统的设计与应用，对其在提高医院工作效率、优
化病历整合与共享机制以及提升医疗质量等方面的作用进行了全面分析。
首先，医院病历管理系统的引入显著提高了医院的工作效率。与传统的纸质病历相比，电子病历系统具有快速记录、查询和共享病历信息的能力，使医生能够更迅速地获取患者的病历资料，从而缩短了诊疗时间，提高了工作效率。此外，系统还具备医生填写医嘱、管理员排班等功能，进一步减轻了医生的工作负担。
其次，医院病历管理系统在病历整合和共享方面表现出色。通过将患者的病历信息集中存储在数据库中，系统实现了跨科室的信息共享，克服了传统纸质病历信息分散、难以整合的弊端。这不仅方便了医生的工作，也促进了医院不同科室之间的协同合作，提高了医疗服务的整体质量。
此外，医院病历管理系统还具有丰富的数据分析功能。系统中的大量病历数据可用于医学研究、统计分析等用途，有助于医院更好地掌握患者的疾病情况和治疗效果，为临床决策提供有力支持。
本文的主要工作内容如下：
（1）在项目初期，通过研究国内外的相关资料，深入了解了病历管理系统的发展背景和现状，并识别出目前病历管理面临的主要问题。基于这些信息，本文对医院病历管理系统进行了详细的需求分析，并设计了相关模块，目的是优化现有病历管理系统，解决已识别的问题。
（2）对系统用户的角色进行深入分析和设计，明确不同角色的权限和功能；构建医院病历管理系统的数据库结构，涵盖实体的定义、关系表的规划以及字段的详细设计。
（3）系统利用Spring Boot框架结合JavaScript进行开发，这不仅使得用户界面更加清晰和吸引人，还因为采用了前后端分离的架构，简化了后续的开发和维护工作，从而有效减少了开发成本。
本系统还存在着一些的不足，整体还需完善以下主要方面：
（1）病历管理系统还将更加注重用户体验和满意度。医院需要不断优化系统的操作流程和功能设计，使其更加符合医生的操作习惯和需求，提高用户的使用体验。同时，医院还需要加强对医生的培训和教育，提高他们对病历管理系统的认知和使用能力，确保系统能够发挥最大的效益。

（3）该系统还可以完善医嘱病历模块，详细了解现实存在的医嘱病历的模板，从而达到美观的医嘱病历模块功能。
