## 第2页：研究背景与痛点
* **研究背景**：
  * 国民慢性病患病率上升，不合理的膳食结构是重要诱因。
  * 传统营养咨询成本高，普通大众难以获得持续的个性化指导。
* **现有系统的痛点**：
  * 推荐结果缺乏个性化，往往是统一的静态食谱。
  * 仅考虑用户口味，忽视了高血压、糖尿病等特殊人群的**健康约束**。
* **开发目标**：
  * 基于协同过滤算法，结合营养学规则，打造一个科学、个性化的饮食推荐平台。

## 第3页：系统整体架构与技术选型
* **架构设计**：前后端分离 + 算法微服务架构
* **核心技术栈**：
  * **主业务后端**：Java / Spring Boot / MyBatis / Spring Security
  * **推荐算法服务**：Python / FastAPI / Scikit-learn / Pandas
  * **用户端前端**：React 18 / TypeScript / TailwindCSS
  * **管理端前端**：Vue.js / Element UI
  * **数据存储**：MySQL 5.7

## 第4页：核心推荐算法体系设计
* **协同过滤算法 (核心)**：
  * 基于矩阵分解 (Matrix Factorization) 模型。
  * 采用随机梯度下降 (SGD) 训练用户和食物的隐因子矩阵，挖掘用户深层口味偏好。
* **混合推荐模型 (Hybrid Recommender)**：
  * 协同过滤 (60%) + 基于内容的推荐 (40%：提取营养与文本TF-IDF特征)。
* **营养学约束规则层**：
  * 算法输出候选集后，加入**疾病约束**（如高血压严格过滤高钠食物）与**营养均衡约束**。

## 第5页：核心功能一（健康档案与饮食记录）
* **健康档案管理**：
  * 采集身高体重，自动计算BMI与BMR（基础代谢率）。
  * 支持设置健康目标（减脂、增肌、维持），记录过敏史与慢性病。
* **智能饮食记录**：
  * 支持食物名称模糊搜索与联想输入。
  * 根据进食份量，系统自动精确换算热量、蛋白质、脂肪和碳水化合物。

## 第6页：核心功能二（智能推荐引擎）
* **全天方案科学生成**：
  * 严格按 3:4:3 热量比例分配早中晚餐。
  * 支持对单品食物点击“换一个”（同类食物替换）。
  * 提供透明的“个性化推荐理由”。
* **三级降级推荐机制（高可用设计）**：
  * 首选：调用 Python 协同过滤服务获取个性化推荐。
  * 降级：算法服务不可用时，使用后端增强规则推荐。
  * 兜底：基础营养搭配推荐。

## 第7页：核心功能三（数据统计与后台管理）
* **可视化健康报告**：
  * 用户端展示多维度营养统计图表。
  * 对比“实际摄入”与“目标摄入”，生成直观的进度条。
* **管理员控制面板**：
  * 维护包含14项详细营养指标的食物库。
  * **算法训练管理**：在后台可一键触发Python服务重新训练协同过滤模型，实时监控训练进度与损失值(Loss)收敛情况。

## 第9页：难点攻克与项目创新点
* **核心难点：新用户的“冷启动”问题**
  * **解决方案**：设计渐进式过渡策略。新用户注册初期依赖其健康档案进行强规则推荐；当积累10条饮食记录后，系统无缝切换至协同过滤算法。
* **创新点1：算法与业务微服务解耦**
  * 采用 Java (处理高并发与权限逻辑) + Python (处理矩阵分解等耗时计算) 的双后端架构。
* **创新点2：兼顾“口味”与“健康”的融合机制**
  * 打破了传统推荐算法仅追求“命中率”的局限，强制将协同过滤结果置于营养学约束规则之下。

## 第10页：总结与展望
* **工作总结**：
  * 独立完成了系统前后端及算法服务的全栈开发。
  * 成功验证了协同过滤结合营养学规则在饮食健康领域的应用价值。
* **未来展望**：
  * 扩充现有的食物数据库规模（目前覆盖核心55种）。
  * 引入更多维度的上下文信息（如季节、天气）优化协同过滤效果。
  * 增加社区分享功能，提升用户粘性。
