## 一、选题背景与意义

### （一）研究背景

随着社会经济的快速发展和人民生活水平的不断提高，居民对健康饮食的需求日益增长。根据《中国居民营养与慢性病状况报告（2023）》，我国成年居民超重率和肥胖率持续上升，高血压、糖尿病、高血脂等慢性疾病患病率不断增加。不合理的饮食结构已成为影响国民健康的重要因素。传统的营养咨询服务成本高昂，且难以满足个性化、实时化的需求。

近年来，人工智能技术的迅猛发展为解决这一问题提供了新的思路。机器学习算法在模式识别、数据挖掘和智能推荐等领域取得了显著成果，为构建智能化的健康饮食推荐系统奠定了技术基础。通过收集用户的基本信息、健康数据、饮食偏好等多维度数据，利用机器学习算法进行深度分析和建模，可以实现精准的个性化饮食推荐，帮助用户科学合理地安排日常饮食，从而改善营养状况，预防和控制慢性疾病。

### （二）研究意义

#### 1. 理论意义

本研究将机器学习技术与营养学知识相结合，探索基于用户健康数据的智能推荐算法，丰富了推荐系统在健康领域的应用理论。通过构建融合营养匹配、健康约束和个性化偏好的多目标优化模型，为健康管理领域的智能化发展提供理论支撑。

#### 2. 实际意义

（1）**提升个性化服务能力**：系统能够根据用户的年龄、性别、身体状况、疾病史、过敏源等个性化信息，自动生成符合其健康需求的饮食方案，克服了传统营养咨询服务覆盖面窄、成本高的局限。

（2）**助力慢性病预防与管理**：通过智能化的营养干预，帮助高血压、糖尿病、痛风等慢性病患者控制饮食，降低疾病风险，提高生活质量。

（3）**促进健康中国战略实施**：响应《"健康中国2030"规划纲要》，利用信息技术推动全民健康管理，具有重要的社会价值。

## 二、国内外研究现状

### （一）国外研究现状

国外在智能饮食推荐领域的研究起步较早。Freyne等（2010）提出了基于协同过滤的食谱推荐系统，通过分析用户的历史行为数据生成推荐列表。Min等（2019）开发了基于深度学习的食物识别与营养分析系统，可以通过图像识别技术自动计算食物的营养成分。Bianchini等（2020）提出了结合用户健康目标和营养需求的混合推荐算法，实现了个性化的膳食规划。

在健康约束推荐方面，Mika等（2021）开发了面向糖尿病患者的智能饮食推荐系统，通过控制碳水化合物摄入和血糖生成指数（GI值）来优化推荐结果。Toledo等（2022）提出了基于知识图谱的营养推荐模型，将食物营养知识与用户健康信息相结合，提高了推荐的准确性和可解释性。

### （二）国内研究现状

国内在智能饮食推荐领域的研究近年来也取得了一定进展。清华大学团队（2021）提出了基于用户画像的个性化营养推荐算法，通过构建多维度用户画像实现精准推荐。浙江大学研究团队（2022）开发了融合中医体质理论的智能饮食推荐系统，将传统中医知识与现代营养学相结合，形成了具有中国特色的推荐模型。

在健康管理应用方面，国内多家互联网企业也推出了相关产品。例如，某健康管理平台利用大数据分析用户饮食习惯，提供个性化的营养建议；某智能硬件厂商开发了智能秤与饮食管理APP的联动系统，实现了数据的自动采集和分析。

### （三）现有研究不足

尽管国内外在智能饮食推荐领域已有一定研究基础，但仍存在以下不足：

1. **健康约束考虑不足**：多数系统侧重于营养成分匹配，对用户的疾病史、过敏源等健康约束考虑不够充分，推荐结果可能存在健康隐患。

2. **个性化程度有限**：现有系统往往采用通用的推荐模型，未能充分考虑个体差异，如不同健康目标（减脂、增肌、保持）下的营养需求差异。

3. **可解释性不强**：基于深度学习的推荐系统虽然准确率高，但缺乏可解释性，用户难以理解推荐理由，影响信任度和接受度。

4. **系统集成度低**：多数研究停留在算法层面，缺少完整的系统设计与实现，难以在实际场景中应用。

## 三、拟研究的主要内容与思路

### （一）研究内容

本研究拟开发一套基于机器学习的智能健康饮食推荐系统，主要研究内容包括：

#### 1. 用户健康信息管理模块

设计并实现用户基本信息（性别、年龄、身高、体重）、健康信息（疾病史、过敏源、饮食偏好）和健康目标（减脂/增肌/保持）的录入、存储与管理功能。基于用户输入的身高和体重，自动计算BMI（身体质量指数）和BMR（基础代谢率），为后续推荐提供数据支撑。

#### 2. 食物营养数据库构建

收集整理常见食物的营养成分数据，包括热量、蛋白质、脂肪、碳水化合物、钠含量、GI值、嘌呤含量等指标。参考《中国食物成分表（2024版）》等权威资料，建立包含不少于50种常见食物的营养数据库。同时，标注食物的适用人群和禁忌人群，为健康约束推荐提供基础。

#### 3. 基于健康约束的智能推荐算法

设计一套融合规则引擎和机器学习的混合推荐算法：

（1）**健康约束规则引擎**：针对高血压、糖尿病、痛风等常见慢性病，制定相应的营养限制规则。例如，高血压患者优先推荐低钠高钾食物；糖尿病患者优先推荐低GI值食物；痛风患者严格排除高嘌呤食物。

（2）**营养匹配算法**：基于用户的BMR、健康目标和活动量，计算每日营养需求（热量、蛋白质、碳水化合物、脂肪）。设计营养匹配评分函数，综合考虑推荐食物与目标需求的匹配度。

（3）**个性化偏好学习**：记录用户的饮食反馈（喜欢/不喜欢），利用协同过滤或深度学习模型学习用户偏好，优化后续推荐结果。

（4）**多样性优化**：在保证营养匹配和健康约束的基础上，引入随机因子和多样性约束，避免推荐结果过于单一，提升用户体验。

#### 4. 饮食记录与营养统计模块

实现用户日常饮食记录的添加、查询和统计功能。支持智能输入联想（输入部分食物名称自动补全）和快速选择功能。自动统计每日、每周的营养摄入情况，生成营养分析报告，帮助用户了解自身饮食状况。

#### 5. 系统集成与前后端开发

采用前后端分离架构，后端基于Spring Boot框架开发RESTful API接口，前端采用React框架构建用户界面。设计直观友好的交互界面，实现用户信息录入、AI推荐、方案调整、饮食记录、营养统计等功能的无缝集成。

### （二）研究思路

#### 1. 需求分析阶段

通过文献研究和用户调研，明确智能饮食推荐系统的功能需求和性能需求。分析目标用户群体（慢性病患者、减肥/增肌人群、健康管理人群）的实际需求，确定系统应具备的核心功能。

**主要方法**：问卷调查、访谈法、文献分析法  
**达到目的**：明确系统边界，制定功能清单

#### 2. 数据准备阶段

收集和整理食物营养数据，参考权威营养学资料，建立标准化的营养数据库。收集用户健康数据样本，分析不同健康状况下的营养需求差异。

**主要方法**：数据采集、数据清洗、数据标注  
**达到目的**：为推荐算法提供高质量的数据基础

#### 3. 算法设计阶段

研究健康约束规则，制定针对高血压、糖尿病、痛风等疾病的营养限制标准。设计营养匹配评分函数，建立食物-用户匹配模型。引入个性化偏好学习机制，优化推荐结果。

**主要方法**：规则建模、数学建模、算法设计  
**达到目的**：构建科学有效的智能推荐算法

#### 4. 系统开发阶段

搭建开发环境，选择技术栈（Spring Boot + React + MySQL）。采用模块化开发方式，先开发后端API服务，再开发前端界面，最后进行前后端联调。遵循敏捷开发模式，快速迭代优化。

**主要方法**：编码实现、单元测试、集成测试  
**达到目的**：实现系统各项功能

#### 5. 测试验证阶段

进行功能测试，验证系统各模块是否正常工作。进行推荐效果测试，评估推荐准确性和用户满意度。进行性能测试，确保系统响应速度和稳定性。

**主要方法**：黑盒测试、白盒测试、用户测试  
**达到目的**：发现并修复问题，优化系统性能

### （三）初步设计方案

#### 1. 系统总体架构

系统采用前后端分离的三层架构模式：

**表示层**：
- 用户端：React 18 + TypeScript + Tailwind CSS（7个功能页面）
- 管理端：Vue 2 + Element UI（4个管理页面）

**业务逻辑层**：
- Spring Boot 2.5框架
- RESTful API设计（20+个接口）
- JWT身份认证
- 推荐算法服务（MySQL存储过程）

**数据访问层**：
- MySQL 8.0关系型数据库
- MyBatis持久层框架
- MongoDB文档数据库（存储饮食记录详情）

#### 2. 功能模块设计

系统划分为6大核心功能模块：

**（1）用户健康信息管理模块**  
- 用户注册与登录（JWT认证）
- 健康信息录入（基本信息、疾病史、过敏源、饮食偏好）
- 健康目标设定（减脂/增肌/保持）
- BMI/BMR自动计算

**（2）智能推荐模块**  
- 个性化推荐算法引擎（6大健康约束规则）
- 健康约束规则处理（高血压、糖尿病、痛风等）
- 营养匹配评分（综合评分函数）
- 全天方案一键生成（早午晚三餐13种食物）
- 单餐推荐（10种食物）
- 方案交互调整（👍喜欢/👎不喜欢/🔄更换）

**（3）饮食记录模块**  
- 智能输入联想（输入"燕"→联想"燕麦"）
- 快速选择功能（8个常用食物）
- 营养数据自动填充
- 记录增删改查
- 历史记录查询（按日期分组）

**（4）营养统计模块**  
- 每日营养汇总（实时SQL计算）
- 每周营养趋势
- 营养目标达成度分析
- 可视化进度条展示

**（5）食物信息模块**  
- 食物营养数据查询（55种食物）
- 食物详情展示（营养成分+功效）
- 健康功效说明（自动生成）
- AI搭配推荐（基于类别智能推荐）
- 适用/不适用人群提示

**（6）推荐方案管理模块**  
- 推荐历史查看（用户端+管理端）
- 方案执行追踪（执行状态同步）
- 用户推荐统计（总数、已执行、待执行）
- 推荐效果分析

#### 3. 数据库设计

**核心数据表**（7个主表）：

- **sys_user**：用户基本信息表（用户名、密码、角色等）
- **sys_user_health**：用户健康信息表（18个字段：性别、年龄、身高、体重、BMI、BMR、疾病史、过敏源、饮食偏好、健康目标、营养目标等）
- **diet_food_info**：食物基本信息表（55种食物）
- **diet_food_nutrition**：食物营养数据表（27个营养指标：热量、蛋白质、脂肪、碳水、钠、GI值、嘌呤等）

- **diet_record**：饮食记录表（用户实际摄入记录）
- **diet_recommendation**：推荐历史表（其他推荐记录）

**表间关系**：
- 所有表通过user_id关联到sys_user
- diet_food_info与diet_food_nutrition通过food_id一对一关联
- diet_ai_recognition与sys_user通过user_id实现用户-方案关联
- diet_record与sys_user通过user_id实现用户-记录关联

## 四、研究的创新点与重点、难点

### （一）研究重点

#### 1. 个性化健康约束推荐算法的设计与实现

针对不同疾病和健康状况的用户，设计6大健康约束规则引擎（高血压约束、糖尿病约束、痛风约束、过敏源排除、饮食偏好调整、健康目标优化），实现真正的差异化推荐。这是系统的核心功能，也是区别于传统推荐系统的关键所在。重点在于规则的科学性、全面性和准确性，确保推荐结果既满足营养需求，又符合健康限制。

#### 2. 营养匹配与目标计算算法

基于用户的BMR、健康目标（减脂/增肌/保持）和活动量，动态计算每日营养需求（热量、蛋白质、碳水化合物、脂肪）。设计营养匹配评分函数，综合考虑推荐食物与目标需求的匹配度。重点在于营养计算的科学性和评分函数的合理性，需要符合《中国居民膳食营养素参考摄入量》标准。

#### 3. 智能交互与用户体验优化

实现智能输入联想（输入部分食物名自动补全并填充营养数据）、一键生成全天方案、方案交互调整（喜欢/不喜欢/更换）、食物详情与搭配推荐等创新交互功能。重点在于降低使用门槛，提升用户体验和系统易用性，让非专业用户也能轻松使用。

#### 4. 双端应用开发与数据互通

开发用户端（React）和管理端（Vue）双端应用，实现数据的完全互通。用户端生成的AI推荐方案在管理端实时可见，管理端可追踪所有用户的推荐历史和执行情况。重点在于前后端架构设计、API接口规范和数据同步机制，确保双端数据一致性。

#### 5. 推荐算法的可解释性设计

为每条推荐结果生成详细的推荐理由（如"✓低钠适合高血压"、"✓高蛋白促进肌肉生长"、"⚠️高GI不适合糖尿病"），让用户理解推荐依据，提升系统的透明度和可信度。重点在于推荐理由的生成逻辑和文本表达，确保解释清晰易懂。

### （二）研究难点

#### 1. 多约束条件下的推荐优化问题

用户可能同时患有多种疾病（如既有高血压又有糖尿病），或存在多种饮食限制（既过敏海鲜又偏好素食），如何在满足所有约束条件的同时，保证推荐结果的营养合理性和多样性，是一个多目标优化难题。需要设计合理的约束优先级和冲突解决机制。

**难点解决方案**：采用分层过滤策略，先进行硬约束过滤（过敏源完全排除DELETE FROM），再进行软约束评分（疾病限制降低评分UPDATE SET score = score - N），最后进行营养匹配和多样性优化（综合评分+随机因子）。通过综合评分函数平衡各项指标。

#### 2. 推荐算法的准确性与实时性平衡

推荐算法需要考虑多维度数据（用户信息、营养数据、健康约束、历史偏好），计算复杂度较高。同时，用户期望快速获得推荐结果（3秒内），如何在保证推荐准确性的前提下，提升算法的执行效率，是技术难点。

**难点解决方案**：采用MySQL存储过程封装核心算法逻辑，利用数据库的高效查询能力。通过建立索引（user_id、food_id、gi_value、sodium_per_100g）、SQL优化（避免子查询）、临时表机制（temp_recommendations）等手段提升性能。设计算法缓存机制，避免重复计算。

#### 3. 前后端数据一致性与同步

系统包含用户端（3000端口）和管理端（81端口）两个前端应用，共享同一后端数据库（diet_ai_recognition、sys_user_health等表）。如何确保两端数据的一致性，避免数据冲突和延迟，是系统集成的难点。同时，用户修改健康信息后需自动触发推荐更新，涉及多模块间的联动。

**难点解决方案**：采用统一的数据表设计，通过RESTful API统一数据访问入口。实现事务管理（@Transactional）确保数据一致性。设计事件驱动机制，用户信息更新后自动触发推荐算法调用（triggerAIRecommendation函数）。通过定时刷新或消息推送实现数据的准实时同步。

### （三）研究创新点

#### 1. 差异化健康约束推荐

针对不同疾病和健康状况的用户，设计了6大健康约束规则引擎，实现了真正的个性化推荐。系统不仅考虑营养需求，更关注健康安全，确保推荐结果符合用户的健康限制。这是对传统推荐系统的重要创新。

**创新体现**：
- 高血压患者：自动控制钠摄入（sodium<200mg），低钠食物评分提升20分
- 糖尿病患者：严格限制GI值（gi_value<55），低GI食物评分提升25分
- 痛风患者：黑名单机制，完全排除高嘌呤食物（purine>100mg直接DELETE）
- 过敏源处理：智能识别并排除过敏食物类别（海鲜/坚果/乳制品等）

#### 2. 营养目标动态联动机制

用户修改健康信息或目标后，系统自动触发AI重新生成推荐方案，实现了"信息-推荐-执行-反馈-优化"的完整闭环。这种动态联动机制使推荐始终贴合用户的最新需求，是系统智能化的重要体现。

**创新体现**：
- 保存健康信息 → 自动调用推荐API（handleSaveGoal → triggerAIRecommendation）
- 修改健康目标 → 自动调整营养需求（减脂0.85系数，增肌1.15系数）
- 执行推荐方案 → 自动转为饮食记录（diet_ai_recognition → diet_record）
- 营养超标提醒 → 调整下餐推荐策略

通过设计对比实验，验证不同推荐算法的效果，评估系统的推荐准确性、用户满意度和健康效果。

### （二）技术路线

#### 1. 数据采集与预处理

（1）**食物营养数据采集**：从《中国食物成分表》、权威营养学资料中收集55种常见食物的营养成分数据，包括宏量营养素（热量、蛋白质、脂肪、碳水化合物）和微量元素（钠、钙、铁等），以及GI值、嘌呤含量等健康指标。

（2）**用户数据采集**：设计用户信息录入界面，收集基本信息（性别、年龄、身高、体重）、健康信息（疾病史、过敏源、饮食偏好）和健康目标（减脂/增肌/保持）。

（3）**数据预处理**：对收集的数据进行清洗、规范化处理，确保数据质量。建立数据验证机制，对异常数据进行标注和处理。

#### 2. 智能推荐算法设计

（1）**健康约束规则引擎**：

- 高血压约束：sodium_per_100g < 200mg，优先high_potassium食物
- 糖尿病约束：gi_value < 55，carbohydrate_per_100g控制
- 痛风约束：purine_per_100g < 100mg（严格排除）
- 过敏源黑名单：完全排除过敏食物类别

（2）**营养匹配算法**：

基于用户BMR和健康目标计算营养需求：
```
目标热量 = BMR × 活动系数 × 目标系数
其中：
- 减脂：目标系数 = 0.85
- 增肌：目标系数 = 1.15
- 保持：目标系数 = 1.00

蛋白质需求 = 体重(kg) × 蛋白质系数
其中：
- 减脂：1.2g/kg
- 增肌：2.0g/kg
- 保持：1.0g/kg
```

设计综合评分函数：
```
Score = 健康约束分(0-100) + 营养匹配分(0-100) + 偏好分(0-50) + 多样性因子
```

（3）**个性化偏好学习**：
- 记录用户对推荐食物的反馈（喜欢/不喜欢）
- 构建用户-食物交互矩阵
- 应用协同过滤或矩阵分解算法学习用户偏好

（4）**多样性优化**：
- 引入随机因子避免重复推荐
- 控制同类食物比例
- 保证食物类别多样性

#### 3. 系统架构设计

采用前后端分离的B/S架构：

（1）**后端架构**：
- 框架：Spring Boot 2.5 + MyBatis
- 数据库：MySQL 8.0 + MongoDB（存储详细饮食记录）
- 推荐引擎：MySQL存储过程实现核心算法
- API设计：RESTful风格接口

（2）**前端架构**：
- 用户端：React 18 + TypeScript + Tailwind CSS
- 管理端：Vue 2 + Element UI
- 状态管理：React Hooks
- 数据交互：Axios

（3）**数据库设计**：
- sys_user_health：用户健康信息表
- diet_food_nutrition：食物营养数据表
- diet_ai_recognition：AI推荐方案表
- diet_record：饮食记录表
- diet_recommendation：推荐历史表

#### 4. 核心功能实现

（1）**智能推荐生成**：
- 实现一键生成全天饮食方案（早午晚三餐）
- 支持单餐推荐（早餐/午餐/晚餐/加餐）
- 实时调整优化（喜欢/不喜欢/更换食物）

（2）**饮食记录管理**：
- 智能输入联想（输入"燕"自动联想"燕麦"）
- 自动填充营养数据
- 饮食历史查询与统计

（3）**健康目标设定**：
- 用户信息录入与修改
- 目标设定（减脂/增肌/保持）
- 目标变化自动触发重新推荐

（4）**食物详情与搭配**：
