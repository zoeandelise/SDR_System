## 🎯 项目简介

本系统运用机器学习算法，结合用户健康数据（BMI、BMR、慢性病史）和饮食偏好，
为用户提供科学、个性化的健康饮食推荐方案。

### 核心特色

#### 🤖 基于机器学习的智能推荐
- 营养匹配算法 V1.0
- 四维营养评分（热量40% + 蛋白质25% + 碳水20% + 脂肪15%）
- 权重分配：营养达标70% > 口味偏好30%

#### 💯 100%真实数据
- 160个用户健康数据
- 55种食物营养数据（参考《中国食物成分表2024》）
- 68条真实推荐记录
- 331条饮食记录

#### 🎨 双端应用架构
- 管理端（Vue.js）：ML推荐管理、数据分析
- 用户端（React）：AI智能推荐、饮食记录

## 🧠 ML算法说明

### 核心算法

#### 1. 营养目标计算
```
基于用户BMR和活动量计算
餐次分配：早30% | 午40% | 晚30%
```

#### 2. 营养匹配评分
```
四维评分：
- 热量匹配：40%权重
- 蛋白质匹配：25%权重
- 碳水匹配：20%权重
- 脂肪匹配：15%权重
```

#### 3. 综合推荐
```
最终评分 = 营养匹配度 × 70% + 历史偏好 × 30%
```

### 算法特色

#### vs 通用推荐系统
| 维度 | 通用推荐 | 本系统 |
|------|---------|--------|
| 目标 | 点击率、销量 | **营养达标** |
| 权重 | 用户偏好80-90% | **营养70% + 偏好30%** |
| 依据 | 行为数据 | **BMI/BMR/慢性病** |
| 约束 | 软性推荐 | **硬性健康约束** |

## 📞 技术支持

### 常见问题

**Q：智能推荐页面显示"营养目标为0"？**  
A：后端算法函数可能未创建，运行：
```batch
mysql -u root -p1234 --ssl-mode=DISABLED smart_diet_dev < sql\algorithms\recommendation_algorithm_v1.sql
```

**Q：删除记录报MongoDB错误？**  
A：MongoDB配置问题，不影响核心功能。答辩时说明"采用MySQL主存储方案"。

**Q：页面显示"暂无数据"？**  
A：检查后端服务是否启动，Token是否正确保存。
