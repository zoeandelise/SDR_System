# 健康饮食推荐算法设计文档 V1.0

## 一、算法概述

### 1.1 设计理念
**"营养优先 + 偏好过滤 + 反馈优化"三层架构**

- **第一层：营养匹配**（权重70%）
  - 基于用户BMR、BMI、营养目标
  - 计算食物与目标营养素的匹配度
  - 热量、蛋白质、碳水、脂肪四维评分

- **第二层：偏好过滤**（硬性约束）
  - 饮食偏好标签（素食/低糖/低盐等）
  - 不喜欢的食材列表
  - 过敏原排除（待数据补充）

- **第三层：历史反馈**（权重30%）
  - 基于历史推荐的用户评分
  - 优先推荐高接受率食物
  - 持续学习用户偏好

### 1.2 核心优势
✅ **完全基于现有数据**：不依赖未补充的GI值、钠等数据  
✅ **SQL原生实现**：可直接在数据库中执行，性能高  
✅ **易于扩展**：预留接口，补充数据后无需重构  
✅ **可验证**：使用68条历史推荐记录验证准确性

## 二、算法流程

### 2.1 完整流程图

```
用户输入(user_id, meal_type)
         ↓
[步骤1] 查询用户健康数据
         ↓ (sys_user_health表)
       获取：BMI, BMR, 营养目标, 饮食偏好, 不喜欢食材
         ↓
[步骤2] 计算单餐营养目标
         ↓ (calculate_meal_nutrition_target函数)
       早餐30% | 午餐40% | 晚餐30% | 加餐10%
         ↓
[步骤3] 查询候选食物
         ↓ (diet_food_info + diet_food_nutrition表)
       条件：status='0' AND calories>0
         ↓
[步骤4] 偏好过滤
         ↓
       排除：food_dislikes中的食材
         ↓
[步骤5] 营养匹配评分
         ↓ (calculate_nutrition_match_score函数)
       热量40% + 蛋白质25% + 碳水20% + 脂肪15%
         ↓
[步骤6] 历史反馈加权
         ↓ (查询diet_recommendation表)
       营养匹配70% + 历史评分30%
         ↓
[步骤7] 排序输出
         ↓
       按final_score降序，返回TOP N
```

### 2.2 数据表使用明细

| 步骤 | 数据表 | 使用字段 | 作用 |
|------|--------|----------|------|
| 1 | sys_user_health | user_id, bmi, bmr, daily_calorie_goal, daily_protein_goal, daily_carb_goal, daily_fat_goal, diet_preferences, food_dislikes | 获取用户健康数据和偏好 |
| 3 | diet_food_info | food_id, food_name, category_id, status | 获取食物基础信息 |
| 3 | diet_food_nutrition | food_id, calories, protein, carbohydrate, fat | 获取食物营养数据 |
| 3 | diet_food_category | category_id, category_name | 获取食物分类信息 |
| 6 | diet_recommendation | user_id, recommended_foods, score, is_accepted | 获取历史反馈数据 |

## 三、核心函数详解

### 3.1 函数1：calculate_meal_nutrition_target

**功能**：计算用户单餐营养目标

**输入参数**：
- `p_user_id` (BIGINT): 用户ID
- `p_meal_type` (VARCHAR): 餐次类型（'0'=早餐, '1'=午餐, '2'=晚餐, '3'=加餐）

**输出**：JSON格式
```json
{
  "target_calories": 840,
  "target_protein": 35.4,
  "target_carb": 128.34,
  "target_fat": 25.92,
  "meal_ratio": 0.40
}
```

**计算逻辑**：
```sql
-- 餐次营养分配比例
早餐: daily_goal × 0.30
午餐: daily_goal × 0.40
晚餐: daily_goal × 0.30
加餐: daily_goal × 0.10
```

**使用示例**：
```sql
-- 查询用户101的午餐营养目标
SELECT calculate_meal_nutrition_target(101, '1');
```

---

### 3.2 函数2：calculate_nutrition_match_score

**功能**：计算食物与目标营养的匹配度评分（0-100分）

**输入参数**：
- 食物营养：`p_food_calories`, `p_food_protein`, `p_food_carb`, `p_food_fat`
- 目标营养：`p_target_calories`, `p_target_protein`, `p_target_carb`, `p_target_fat`

**评分算法**：

| 营养素 | 权重 | 满分范围 | 扣分规则 |
|--------|------|----------|----------|
| 热量 | 40% | 目标±20% | 超出范围线性扣分 |
| 蛋白质 | 25% | 目标±30% | 超出范围线性扣分 |
| 碳水化合物 | 20% | 目标±30% | 超出范围线性扣分 |
| 脂肪 | 15% | 目标±30% | 超出范围线性扣分 |

**计算公式**：
```
总分 = 热量分×0.40 + 蛋白质分×0.25 + 碳水分×0.20 + 脂肪分×0.15
```

**示例**：
```sql
SELECT calculate_nutrition_match_score(
    500,  -- 食物提供500kcal
    25,   -- 蛋白质25g
    60,   -- 碳水60g
    15,   -- 脂肪15g
    600,  -- 目标600kcal
    30,   -- 目标蛋白质30g
    70,   -- 目标碳水70g
    20    -- 目标脂肪20g
) AS match_score;
-- 结果：约85.5分（热量-17%, 蛋白质-17%, 碳水-14%, 脂肪-25%）
```

### 3.3 函数3：generate_personalized_recommendation（存储过程）

**功能**：为用户生成完整的个性化推荐列表

**输入参数**：
- `p_user_id` (BIGINT): 用户ID
- `p_meal_type` (VARCHAR): 餐次类型
- `p_recommendation_count` (INT): 推荐数量

**输出**：结果集，包含以下字段
- `food_id`: 食物ID
- `food_name`: 食物名称
- `category_name`: 分类名称
- `calories_per_100g`: 每100g热量
- `nutrition_score`: 营养匹配度（0-100）
- `history_score`: 历史反馈分（0-100）
- `final_score`: 综合评分
- `recommended_portion`: 建议份量(g)
- `recommendation_reason`: 推荐理由

**核心SQL逻辑**：
```sql
SELECT 
    f.food_name,
    -- 营养匹配度(70%)
    calculate_nutrition_match_score(...) AS nutrition_score,
    -- 历史反馈(30%)
    (SELECT AVG(score) FROM diet_recommendation WHERE ...) AS history_score,
    -- 综合评分
    (nutrition_score * 0.70 + history_score * 20 * 0.30) AS final_score
FROM diet_food_info f
WHERE f.food_name NOT IN (用户不喜欢的食材)
ORDER BY final_score DESC
LIMIT N
```

**使用示例**：
```sql
-- 为用户101生成5个午餐推荐
CALL generate_personalized_recommendation(101, '1', 5);
```

## 五、与未来数据的衔接

### 5.1 扩展接口设计

算法预留以下扩展点，补充数据后可无缝接入：

#### 接口1：GI值过滤（糖尿病用户）
```sql
-- 在generate_personalized_recommendation中添加
WHERE (
    v_user_diseases NOT LIKE '%diabetes%' 
    OR n.gi_value IS NULL 
    OR n.gi_value < 55  -- 低GI食物
)
```

#### 接口2：钠含量过滤（高血压用户）
```sql
WHERE (
    v_user_diseases NOT LIKE '%hypertension%'
    OR n.sodium_per_100g IS NULL
    OR n.sodium_per_100g < 300  -- 低钠食物
)
```

#### 接口3：嘌呤过滤（痛风用户）
```sql
WHERE (
    v_user_diseases NOT LIKE '%gout%'
    OR n.purine_per_100g IS NULL
    OR n.purine_per_100g < 50  -- 低嘌呤食物
)
```

#### 接口4：适用人群标签过滤
```sql
WHERE (
    n.unsuitable_for IS NULL
    OR n.unsuitable_for NOT LIKE CONCAT('%', v_user_diseases, '%')
)
```

### 5.2 扩展步骤

1. **补充营养数据**（执行 `import_food_nutrition_data.sql`）
2. **应用健康规则**（执行 `food_health_rules.sql`）
3. **修改推荐函数**（添加上述WHERE条件）
4. **重新验证**（运行 `algorithm_validation.sql`）

### 6.2 集成到后端

在Java后端调用：
```java
// 1. 创建Mapper接口
public interface RecommendationMapper {
    List<RecommendationResult> generateRecommendation(
        @Param("userId") Long userId,
        @Param("mealType") String mealType,
        @Param("count") Integer count
    );
}

// 2. 创建XML映射
<select id="generateRecommendation" resultType="RecommendationResult">
    CALL generate_personalized_recommendation(
        #{userId}, #{mealType}, #{count}
    )
</select>

// 3. 在Controller中调用
@GetMapping("/recommend")
public AjaxResult recommend(@RequestParam Long userId, 
                           @RequestParam String mealType) {
    List<RecommendationResult> recommendations = 
        recommendationMapper.generateRecommendation(userId, mealType, 10);
    return AjaxResult.success(recommendations);
}
```
