### 场景1：为用户生成推荐（SQL方式）

```sql
-- 普通推荐
CALL generate_personalized_recommendation(101, '1', 10);
```

### 场景2：通过后端API调用

```bash
# 生成推荐
curl -X POST "http://localhost:8080/diet/smart/recommend" \
     -H "Content-Type: application/json" \
     -d '{"userId":101,"mealType":"1","count":10}'

# 获取营养目标
curl "http://localhost:8080/diet/smart/nutrition-target?userId=101&mealType=1"
```

### 场景3：集成到前端

```javascript
// 1. 创建API接口文件
// src/api/diet/smart.js
export function getSmartRecommendation(data) {
  return request({
    url: '/diet/smart/recommend',
    method: 'post',
    data: data
  })
}

// 2. 在组件中调用
async loadRecommendations() {
  const response = await getSmartRecommendation({
    userId: this.userId,
    mealType: '1',
    count: 10
  });
  this.recommendations = response.data.recommendations;
}
```

## 🎓 核心技术亮点

### 1. 完全基于真实数据，拒绝假数据
- ✅ 160个真实用户健康数据
- ✅ 55种真实食物营养数据
- ✅ 68条真实推荐反馈记录
- ❌ 零模拟数据，零硬编码

### 2. 专为健康饮食场景设计

#### 独特设计1：营养优先于口味
```
权重分配：
- 营养匹配度：70% ⭐ 健康第一
- 历史偏好：30%

vs 通用推荐：
- 点击率/销量：80-90%
- 其他因素：10-20%
```

#### 独特设计2：基于生理指标个性化
```
计算公式（Harris-Benedict）：
男性 BMR = 88.362 + (13.397×体重) + (4.799×身高) - (5.677×年龄)
女性 BMR = 447.593 + (9.247×体重) + (3.098×身高) - (4.330×年龄)

vs 通用推荐：
仅基于行为数据（浏览、点击、购买）
```

#### 独特设计3：硬性健康约束
```sql
-- 糖尿病用户强制过滤
WHERE (diseases NOT LIKE '%diabetes%' OR gi_value < 55)

-- 痛风用户强制过滤
WHERE (diseases NOT LIKE '%gout%' OR purine_per_100g < 50)

vs 通用推荐：
软性偏好推荐，无强制约束
```

### 3. 三层优化机制

```
第一层：营养匹配（权重70%）
  ├─ 热量匹配（40%）
  ├─ 蛋白质匹配（25%）
  ├─ 碳水匹配（20%）
  └─ 脂肪匹配（15%）

第二层：多样性优化
  ├─ 近期推荐惩罚（7天重复降权30-70%）
  ├─ 分类多样性保障（确保3+类食材）
  └─ 随机因子（30%推荐结果不同）

第三层：个性化过滤
  ├─ 不喜欢食材排除
  ├─ 过敏原排除
  ├─ 慢性病规则过滤（GI/钠/嘌呤）
  └─ 饮食偏好匹配
```
